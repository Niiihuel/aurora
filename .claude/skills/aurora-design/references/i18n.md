# Languages in aurora

aurora ships in **English and Spanish from day one**, and every new string is added in both in the same change. English is the reference; more languages must be addable by dropping in one file.

## How it works

- Strings live in `shell/i18n/<code>.json` as flat keys: `"area.thing": "Text"`. `en.json` is the reference and the fallback.
- QML never shows a literal: `text: I18n.tr("sound.title")`.
- Variables: `I18n.tr("battery.remaining", { time: "2:15" })` with `"{time} remaining"` in the file.
- Plurals: pass `count`; define `key_one` and `key_other` (`"bluetooth.devices_one": "{count} device"`). Languages with more forms can add them later in `tr()`.
- Dates, times and numbers use `I18n.locale` (Settings.locale, or the language's region: es → es_AR, en → en_US). Never format a date with a hard-coded locale.
- The language comes from `Settings.language` ("en", "es"; empty = system) and switches live: bindings that call `I18n.tr` re-evaluate.

## Rules for new work

1. Add the key to **every** file in `shell/i18n/` in the same change: English first, then a real Spanish translation (not a copy of the English).
2. Key names: `area.thing[.detail]` in lowerCamel segments, named by meaning, not by the English words (`network.otherNetworks`, not `network.other_networks_label`). Group by surface: `bar.*`, `sound.*`, `network.*`, `bluetooth.*`, `battery.*`, `system.*`, `common.*` for shared words (`common.settings`, `common.on`).
3. Spanish follows Apple's Spanish (Latin America), which addresses people as **tú** ("¿Seguro que quieres…?", "Si no haces nada…"), even though the user writes with voseo. Follow each language's Apple conventions: English uses title case in menus ("Sound Settings…"); Spanish uses sentence case ("Configuración de sonido…"), as macOS does in Spanish. Keep the ellipsis (…) where the action asks for more input.
4. Brand and proper names (aurora, device names from the system, network names) are not translated; if one sits in a `text:` literal, end the line with `// i18n-ignore`.
5. Keys built at runtime (`"network.security." + kind`) can't be found by the scan: declare them next to the code in a comment, `// i18n-keys: network.security.open network.security.wpa2`.
6. Run `python3 scripts/check-i18n.py shell` (or `nix flake check`). It fails on a key missing from any language, files that disagree, or a visible plain-string literal outside dev-only files (gallery.qml).

## Adding a language

Copy `en.json` to `<code>.json`, translate every value (keep `_meta.name` as the language's own name), add the code to `I18n.available`, add its default region to `I18n.locale`'s map, and run the check.
